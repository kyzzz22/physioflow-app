# Composer V2 可用性验收规程

本规程用于验证 `SYSTEM_REFACTOR_PLAN.md` 中的上手效率、编辑效率和清晰度指标。自动化测试不能替代本规程的真人结果。

## 参与者与环境

- 初学者组和有实验设计经验组各至少 5 人；参与者不得是本次功能的实现者。
- 使用全新浏览器配置或清空后的本地工作区，1280 × 800 或更大视口。
- 任务开始前只说明产品目标，不演示具体操作；需要提示时记录提示内容和时间。
- 使用虚构参与者编号和无识别性素材，不收集真实实验或个人敏感数据。

## 代表任务

1. 从空项目创建“说明 → 图片刺激 → 1–7 分量表 → 结束”，修复所有阻塞错误并打开预览。
2. 为量表配置必填响应和导出字段；记录完成配置所需的主要点击、输入或连接操作数。
3. 在预置的错误协议中定位并修复一个缺失必需连线和一个无效变量绑定，不允许阅读 JSON。
4. 完成一次预览运行，保存会话，打开 Session Review，并导出完整数据包。
5. 在 Advanced 模式发布并实例化一个带输入/输出映射的子流程；安装示例组件和模拟设备连接器。

## 通过标准

- 任务 1 从新项目到可预览的中位时间不超过 600 秒。
- 任务 2 的常用节点配置主要操作数不超过 8。
- 所有核心任务无需帮助完成的比例至少为 80%，并分别报告两个组的结果。
- 任务 3 的错误均能被参与者定位到节点、属性或连线。
- 任务 4 的预览与正式运行使用相同组件表现；导出包通过独立验证器。
- 阻塞或数据完整性级缺陷必须归零，其他缺陷要有负责人和处理结论。

## 结果签收

设计者签收流程表达与界面清晰度，操作员签收运行与恢复，数据分析人员签收导出与数据字典。将原始记录、汇总统计、缺陷清单和三方结论附在试点报告中；未达到任一阈值时不得把正式可用性标为完成。
